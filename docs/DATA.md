# Данные

## Источники

| Источник | Что даёт |
| --- | --- |
| AniList (GraphQL) | каталог, список пользователя, тайтлы, люди, расписание |
| Шикимори (REST + GraphQL) | русские имена, описания, хронология, журнал, поиск по-русски |
| anime365 | русские названия и описания по номеру MAL |
| AnimeThemes | опенинги и эндинги |
| Kodik, Aniliberty | видео — см. `VIDEO.md` |
| Яндекс Диск | облачная копия списка |
| `animori-data` | датасет русских названий и карта MAL ↔ AniList |

Клиенты — `src/shared/api/`, стратегия — `src/shared/core/`. Зависимости идут
из `api` в `core`, не наоборот.

## Номера

Одному номеру MAL отвечают несколько записей AniList: служба дробит часть на
этапы, оставляя номер общим. Порядок записей и то, какая из них представляет
часть, решает `core/media-parts.ts` (`orderParts`, `pickEntry`). Перевод
номера MAL в AniList идёт только через него.

## Датасет названий

Собирается в отдельном репозитории `foulnike/animori-data` и выходит раз в
неделю. Клиент тянет его сам:

1. при старте `updateDatasetNamesInBackground()` спрашивает опись `index.json`
   по постоянному адресу `releases/latest/download`, с `If-None-Match`;
2. `304` означает «тот же выпуск» — тела нет, сравнивать нечего;
3. если выпуск новее, качаются оба файла, сверяются по `sha256` и заменяют
   слепок целиком;
4. новый выпуск начинает работать со следующего запуска: в память текущего он
   не попадает.

Между проверками — `LIFE_DATASET_CHECK` (12 часов). Разброс считается от даты
установленной сборки, а не от момента установки: иначе все копии лезли бы за
обновлением в один час после публикации. Неудача час проверки не сдвигает.

Зеркала у клиента нет: файлы выпусков посторонние CDN не раздают.

### Если выпуск перестал выходить

Сборку запускают руками: `foulnike/animori-data` → Actions → `build-names` →
**Run workflow**. Прогон идёт до полутора часов, волна карты и публикация
включены по умолчанию.

Приёмка сборки не выпускает половину датасета: пороги — 25 000 названий,
усадка не более 5 % против прошлого выпуска, старший номер не ниже прошлого,
карта не меньше семени на те же 5 %. Не взято — выпуска нет намеренно.

Клиенты в это время живут на предыдущем выпуске, а чего в нём нет — спрашивают
в сети по ходу. Срочности нет, но и тянуть незачем.

Ежедневный сторож, который сам заводит задачу при замирании сборки, лежит в
репозитории десктопной сборки и в этом — нет. Расписание работает только из
ветки по умолчанию, поэтому две копии дали бы две задачи на одну и ту же беду.

## Темп и здоровье

`api/rate-limit.ts` — один ограничитель на источник: лимит считается по IP, а не
по клиенту. `once()` склеивает одинаковые вопросы, пауза считается по остатку
окна.

`core/net-health.ts` ведёт учёт доступности: суждение одно (`getOutage`),
проба одна (`runProbes`), не чаще `PROBE_COOLDOWN_MS` и не поверх идущего. Это
не выключатель, а повод заговорить с человеком — после двух неудач подряд.
Хостов в модуле нет намеренно: список устарел бы за неделю.

## Прокси

Каналов три:

1. запросы приложения — через мост, `basicAuth` в `TauriBridge.ts`;
2. запросы к AniList — из процесса оболочки, `anilist.rs`;
3. канал самого окна — `proxy.rs`, только Windows и WebView2.

На приставке работает два из трёх: канала окна нет.

Проверка — живым запросом через мост (`api/proxy-check.ts`): TCP-щуп в
`proxy.rs` видит лишь приём соединения, а наружу прокси мог не пустить. Исход
пробы в `net-health` не идёт: там отказы источников, здесь настройка, и одна
неудача попала бы в сводку дважды.

Смена адреса требует перезапуска для канала окна; запросы программы
подхватывают её сразу.

## Различение «нет» и «не доехало»

`null` означает и «перевода нет», и «ответ не доехал». Источник отвечает
`ready` / `none` / `fail`, и сбой не запоминается: иначе пачечное «имени нет»
глушило бы открытую карточку того же тайтла.

Отказы держатся отдельными ключами — `memory`, `names`, `noname`.

## Сроки

`core/cache-life.ts` — одно место на всех. Разброс ±20 % считается от ключа, а
не случайно: иначе запись то свежая, то просроченная при каждом чтении.
Бессрочное — тоже срок, `LIFE_FOREVER`, а не «сто лет».

## 18+

Отбор — только через `core/adult.ts`, по тумблеру `settings.showAdult`. Отбор
на слое показа: прячется карточка, а не вход в плеер; свой список не
исключение. Возраст формальный: `ADULT_AGE`, `ageAt`, `adultByBirth`.

У строк отбора метки нет: тэги бьются разделом целиком. Полки витрины
собираются заранее и сбрасываются `forgetRecs()` при смене тумблера.

Взрослых источников видео у приложения нет.

## Грабли чужих API

- **Шикимори.** Зеркала `shikimori.io` (впереди) и `shikimori.rip`; рабочий
  адрес переживает перезапуск. Куки не шлём: `include` давал 400 от размера
  заголовка. Дат в закладках нет вовсе — журнал (`/api/users/:id/history`)
  единственный их источник, причём `target_type` в ответе отсутствует и
  достаётся из `target.url`. Страницы журнала перекрываются на одну запись,
  поэтому шаг равен `limit - 1`.
- **AnimeThemes.** Отказ приходит с кодом 200 и лежит в `errors`: по статусу
  его не отличить от «тем нет».
- **Kodik.** Перечня номеров не принимает ни в одной форме: метка доступности
  стоит поштучно (`presenceCost: 'each'`).
- **AniList.** Расписание: `airingSchedules` — список, а не соединение;
  границы окна строгие. `pageInfo.total` упирается в 5000.
- **anime365.** Источник нестабилен: 403 означает блокировку, а не пустоту.
